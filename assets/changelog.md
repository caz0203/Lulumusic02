## 1.10.2 · 2026-09-23

### 桌面歌词：只剩歌词

- **去掉了背景胶囊**，歌词直接浮在屏幕上；改用**描边**保证可读（描边颜色按当前行明暗自动选黑或白）。

- 上一首 / 播放暂停 / 下一首 用系统播放卡片自带的。

- ⚠️ 说明：Android 13+ 的通知卡片由系统渲染，**部分手机会隐藏自定义按钮**。如果装上去没看到它们，用「设置 → 播放设置 → 桌面歌词」里的两个开关（开关和锁定都在那儿），功能不受影响。

| 项 | 说明 |
|---|---|

- 现在改用系统预定义的振动效果（轻触 / 点击 / 重击 / 双击），比自定义时长可靠得多，老系统自动回退到加长的自定义振动。

## 1.10.1 · 2026-09-23

### 修复：桌面歌词的「关闭」点不动

- **根因**：上一版把「锁定」实现成让整条悬浮窗完全不接收触摸（为了能点穿到下面的 App）。副作用是锁定时**连「关闭」和「解锁」也一起点不动了**，只能回 App 设置里关。

- 代价（必须说明）：窗口既然要接收点击，就**不能再点穿**悬浮条去点下面的 App 了。这是「按钮随时可点」的交换。

- 悬浮条**默认只显示两行歌词**，没有任何按钮，更干净。

  - **锁定/解锁**、**关闭**
  - **背景透明度**滑杆
- **暂停后悬浮条继续显示**（以前暂停就自动收起）。现在只要还有当前歌曲就显示，只有在没有歌曲 / 队列清空时才隐藏。

## 1.10.0 · 2026-09-22

### 修复：桌面歌词现在能显示了

- **根因与权限无关**：悬浮歌词用的是一个自建的 Compose 宿主，它的初始化顺序写错了——在生命周期已经离开初始状态之后才去做 `performAttach`，AndroidX 会直接抛异常。于是**每一次**挂载都在创建视图时就失败，被上层兜底成一句笼统的「桌面歌词无法显示」。现在按 AndroidX 要求的顺序执行，并加了测试钉住这个顺序，防止以后再写反。
- **失败不再吞掉原因**：以前无论什么原因都只弹「桌面歌词无法显示」，而日志里连异常信息都被丢掉了。现在会按真实原因分开提示：没授权 / 系统拒绝了窗口 / 视图创建失败 / 未能识别。系统拒绝那一类还会提示部分国产 ROM 需要额外允许「后台弹出界面」。
- **新增「重试」**：授权之后如果悬浮条没出来，桌面歌词那一行会显示原因并给出「重试」按钮（以前授权成功后「去授权」入口就消失了，等于没有路可走）。

### 界面：设置行整体改细小紧凑

- 所有**滑杆**默认改用紧凑样式：行高 48dp → 30dp，滑杆 4dp → 2dp，滑块 20dp → 13dp，标签 13sp → 11sp，数值 12sp → 10sp。共 11 处（壁纸模糊度 / 播放速度 / 歌词字号 / 歌词时间轴偏移 / 均衡器各频段 / 低音增强 / 环绕声 / 悬浮底栏等）。
- 所有**分段控件**同步收紧：外框高度 22dp → 14dp，圆角 12dp → 9dp，文字 13sp → 11sp。共 10 处（歌词对齐 / 主题模式 / UI 样式 / 首页来源 / 锁屏歌词模式等）。
- 你圈的歌词那三行（字号 / 对齐 / 偏移）以及均衡器相关分组，行间距统一收到 2dp。
- 只改间距与字号，**没有改动任何功能、取值范围、默认值和存储键**。

## 1.9.6 · 2026-09-22

### 新增：QQ 音乐「网页登录」

QQ 登录面板现在是三段：**扫码登录 / 网页登录 / 粘贴 Cookie**。

你的实测诊断证明：扫码和手机确认都成功、跳转链也拿到了 `p_skey`，但最后一步向 `graph.qq.com` 换 code 时被 QQ 回了 **100035 用户未登录**。这条 OAuth 换取链路由腾讯服务端把关，客户端能调的余地很小。

所以新增了**网页登录**：在应用内打开 QQ 音乐网页，你正常登录（扫码 / 密码都行），App 自动把浏览器会话里的 Cookie 读进来完成登录。**这条路不涉及 appid、不涉及任何密钥、也不走 OAuth 换取**——和网易云一直以来的「网页登录」是同一套机制。

如果网页登录后没读到完整凭证，界面会**如实说明失败**，不会假装成功；「粘贴 Cookie」也保持可用。

### 修复：扫码路径的 Cookie 头

- 以前只从一份**白名单**里挑 Cookie 发送，把跳转链实际下发的 `pt_oauth_token`、`pt_login_type` 丢掉了。现在**整个 Cookie 仓库都发**。
- 补上缺失的 `uin`：`graph.qq.com` 是靠 `uin` 认人的，而我们只有 `p_uin` / `pt2gguin`。现在会从中派生（取不到就不造）。
- 新增诊断项 `authorize.cookies`：只记录**发送了哪些 Cookie 的名字**（不含值），便于进一步定位。

## 1.9.5 · 2026-09-22

### 修复：QQ 授权接口的请求方式

- **1.9.4 修反了方向。** 那一版把换 code 的请求从 POST 改成了 GET，但 QQ 官方返回码表明确写着 **100012 = 「HTTP 请求非 POST 方式」**——这个接口恰恰要求 POST。已改回 POST。
- 现在会把 QQ 的错误码**直接翻译成中文显示在红色提示里**，不用打开诊断也能看到，例如「QQ 拒绝授权：回调地址不合法（100010）」。共收录 24 个常见返回码，未知错误码也会原样显示，绝不吞掉。
- 授权失败时**始终记录响应体**（之前只在部分情况记），并把出错的 Location 放在片段最前面，避免被截断。

### 说明

- 1.9.4 已经是正确的版本，可以继续用；本版只是把请求方法改回 POST 并把错误原因显示清楚。

## 1.9.4 · 2026-09-22

### 修复：QQ 音乐扫码登录

- **扫码本身是成功的，失败发生在之后换取登录凭证的环节**，而旧版把这一步的失败一律报成「QQ 授权失败，请重新扫码」，误导你反复重扫。现在按真实原因分开提示：二维码过期 / 已扫但未确认 / 换凭证失败 / 跳转链没建立 / 跳转链没下发凭证 / 授权接口没返回 code / 音乐接口拒绝 code。只有最后一种才建议重新扫码。
- 换 code 那一步从 POST 表单改为 **GET 查询参数**：OAuth 2.0 授权端点规范要求 GET，POST 表单很可能被服务端忽略，表现正好是「手机确认成功但这边拿不到凭证」。
- 跳转链第一跳失败时不再「空手继续往下走」，而是如实报错。
- 补齐一个旧缺陷：音乐接口拒绝 code 时，以前仍会显示登录成功，但实际拿到的是空壳登录态；现在会明确报错。
- 修复昵称取错字段：登录成功后昵称以前会显示成「登录成功！」这句提示文字。
- 新增**「登录诊断」**：QQ 登录面板下方的胶囊按钮（仅在产生记录时出现），点开可看到每一步的 HTTP 状态、是否拿到跳转地址与 code、脱敏后的响应片段，可一键复制。登录失败时它会变成强调色。

### 说明

- 诊断内容会**先脱敏再落盘**：Cookie 整行抹除，qrsig / skey / p_skey / qqmusic_key / musickey / code / uin 等凭证明文一律替换，不会外泄。
